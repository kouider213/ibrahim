## 1. FIX RAILWAY BACKEND (FAIT ✅)

**Problème:** app Dzaryx (`https://kouider213.github.io/ibrahim/`) bloquée sur "CHARGEMENT…" (écran CA). Backend prod en **crash loop** → 502.

**Diagnostic:**
- Projet Railway `ibrahim-backend` a **2 environnements**:
  - `production` → domaine **`ibrahim-backend-production.up.railway.app`** = celui que l'app appelle vraiment. (env id `d00e54c4-e90e-41f8-a9c5-6049896d022b`)
  - `RAILWAY_TOKEN` → `ibrahim-backend-railwaytoken.up.railway.app` (autre domaine, pas celui de l'app). (env id `ee258739-…`)
  - Backup Render `dzaryx-backend-backup.onrender.com` = MORT.
- Cause racine: **Upstash Redis free quota explosé** → scheduler BullMQ (`bull:Dzaryx-scheduler:repeat`) throw `ReplyError: rate-limited` NON catché → `uncaughtException` → Node meurt → restart boucle → 502.

**Fix appliqué:** variable Railway prod **`JOBS_ENABLED=false`** (voir `backend/src/index.ts:504` → skip `initScheduler()`+`initReminderWorker()`). Backend remonté **ACTIVE stable**, health 200, APIs 🟢. `/api/finance/dashboard` répond (401 sans token = normal).

⚠️ **Effet de bord:** rappels / scheduler / briefing auto sont **OFF** tant que `JOBS_ENABLED=false`.
→ **RÉACTIVÉS le 2026-10-12** (`JOBS_ENABLED=true` via railway CLI + redeploy) après le fix durable. Logs prod: scheduler + reminder-worker actifs, erreur Upstash catchée, health 200. Rappels/briefing de retour.

**FIX DURABLE = FAIT ✅ (2026-10-12, commit `9c81ace`):** garde-fous `process.on('uncaughtException'/'unhandledRejection')` dans `index.ts` + listeners `.on('error')` sur toutes les Queue/Worker BullMQ. Backend survit à Redis HS/saturé. Pushé main → Railway redéployé → health 200 OK. Reste optionnel: réactiver `JOBS_ENABLED=true` (sans risque maintenant) + alléger reminder-worker ou upgrade Upstash.
