## 1. SITE — ce qu'on a construit aujourd'hui (avec le pourquoi)

### 1.1 Suivi d'importation véhicule (A→Z)
- **Quoi** : table `import_orders` (SQL `0022`), n° `IMP-XXXXX`, statuts REQUESTED→…→DELIVERED, page publique `/suivi-import/[ref]`, admin `/admin/import`, email+WhatsApp auto par étape.
- **Pourquoi** : les clients qui commandent un véhicule à importer n'avaient aucun suivi. Demande explicite de Kouider (planifiée la veille).
- **Comment / avec quoi** : mêmes patterns que la réservation (timeline, realtime→remplacé par refresh 25s car RLS protège), clé-service pour l'admin, payload public sanitisé (tél masqué, notes privées cachées).
- **Pourquoi ce choix** : pas de compte (friction diaspora), refresh plutôt que realtime pour ne pas exposer la table en lecture publique.

### 1.2 Capture de leads (immo/vente/packs)
- **Quoi** : `LeadCapture` (bouton « Être rappelé » + mini-form) → `/api/lead` → table `client_leads`. Admin `/admin/leads` (relance WhatsApp, statuts).
- **Pourquoi** : ces 3 sections ne passaient QUE par WhatsApp → contact perdu si le client n'écrit pas. Le lead capture le numéro **avant** WhatsApp.
- **Pourquoi ce choix** : on garde le bouton WhatsApp direct (zéro friction) + on AJOUTE le lead (filet de sécurité). Pas imposé, complémentaire.

### 1.3 Suivi de dossier achat/immo/pack
- **Quoi** : table `dossiers` (SQL `0025`), kinds voiture/immo/pack, refs `VTE-`/`IMM-`/`PCK-`, étapes dédiées par kind, page `/suivi-dossier/[ref]`, admin `/admin/dossiers`, bouton public `StartDossier`.
- **Pourquoi** : Kouider voulait le même suivi que location/import pour l'achat véhicule et l'immobilier.
- **Pourquoi ce choix** : UN système unifié `dossiers` (3 kinds) plutôt que 3 systèmes séparés → plus simple, même résultat.

### 1.4 Emails PRO + multilingue + statuts auto
- **Quoi** : `lib/email.js wrap()` refait (logo, bandeau contact WhatsApp+site cliquables, footer numéro+adresse Maps+avis, preheader). **Tous les emails trilingues FR/AR/EN + RTL arabe**. Email auto à CHAQUE changement de statut (résa/import/dossier). Relance auto leads (cron `lead-followup`, 2j).
- **Pourquoi** : emails « trop secs » et en français seulement ; Kouider veut pro + dans la langue du client (« client arabe → réponse arabe »).
- **Comment** : helper `T(lang,{fr,ar,en})`, langue du client mémorisée (`bookings.client_lang`, `client_leads.lang`, `import_orders.lang`, `dossiers.lang` — SQL `0024`/`0026`).

### 1.5 Messages WhatsApp dans la langue du client + bouton statut/suivi
- **Quoi** : tous les constructeurs WhatsApp (réservation, commande, détails voiture/immo/vente/pack) en FR/AR/EN. Boutons admin « envoyer statut + lien suivi » (résa, import, dossier) dans la langue du client. Badge « langue du client » dans l'admin. Bouton « Traduire en français » (TranslateToFr) sur le texte libre client.
- **Pourquoi** : Kouider doit savoir quelle langue parle le client et répondre dans sa langue ; comprendre un message arabe/anglais.

### 1.6 Newsletter (réparée + médias + traduite)
- **Bugs corrigés** : inscription n'écrivait rien (`upsert onConflict 'email'` vs index `lower(email)`) ; admin voyait 0 abonné (RLS sans policy SELECT, SQL `0023`) ; « envoyer à tous » bloqué (`window.confirm` KO en WebView). 
- **Ajouts** : éditeur riche (photo, vidéo galerie→bucket `videos`, bouton CTA, aperçu live), campagnes **auto-traduites par langue d'abonné** (serverTranslate préserve img/boutons).
- **Pourquoi** : Kouider voulait pouvoir envoyer photos/vidéos + que chaque abonné reçoive dans sa langue.

### 1.7 Notifications Telegram directes
- **Quoi** : `lib/telegramNotify.js` (`TELEGRAM_BOT_TOKEN`+`TELEGRAM_CHAT_ID` sur Vercel) → notif à chaque réservation, lead, dossier, import, abonné newsletter, avis. **Nouveau bot dédié `@Fiknotifsbot`** (chat id `809747124`).
- **Pourquoi** : ne jamais rater une demande. **Vérité dite** : le WhatsApp direct (client tape lui-même) arrive sur WhatsApp, pas Telegram (le site ne voit pas les messages WhatsApp privés sans l'API Business). Telegram = pour les formulaires.

### 1.8 SEO / identité / NAP / cookies
- **Favicon** = déjà le logo (le « globe » = Google pas re-crawlé). **NAP unifié** : adresse officielle `Rue Derbouz Draoua, Houari, Oran 31300` PARTOUT (footer, schema ×3, emails, 3 langues). Schema Organization enrichi (`makesOffer`, `sameAs` Insta/FB/TikTok/Maps, email). **Cookies RGPD** (Accepter/Refuser) + **Microsoft Clarity chargé seulement après consentement**.
- **3 pages SEO** : aéroport-oran, importation-algerie, occasion-oran. **Perf** : polices Google via `<link>`+preconnect (au lieu de `@import` render-blocking).
- **Pourquoi** : être #1 Oran. **Vérité dite** : le ranking = Google Business + avis + NAP + temps, PAS du code.

### 1.9 Numéro WhatsApp centralisé + verrou super admin
- **Quoi** : le n° vient de `site_settings.whatsapp` → changer dans Admin→Paramètres le remplace PARTOUT (29 pages + emails via `refreshBrand()`). Modif **réservée au super admin** (is_super). 3 numéros (principal + 2 associés).
- **Pourquoi** : si Kouider change/perd son numéro, tout doit basculer en 1 endroit. **Limite dite** : wa.me = 1 destinataire (pas de broadcast 3 numéros) ; Telegram garantit de tout recevoir.

### 1.10 Comptes admin (login username, mot de passe oublié, équipe)
- **Quoi** : SQL `0027` (`profiles.username`, `is_super`). Login par **nom OU email** (`resolve-login`) + **mot de passe oublié** (`/reset-password`). `/admin/compte` (changer email/mdp, confirme par mdp actuel). `/admin/equipe` (super admin : créer/lister admins, **réinitialiser** mdp, changer email/rôle/username, supprimer) — panneaux intégrés (pas de `window.prompt`, bloqué en WebView).
- **Pourquoi** : Kouider/Houari avaient un email de login bidon ; il veut gérer les accès, ajouter des employés. **Vérité dite** : les mots de passe sont chiffrés, **non lisibles** même par le super admin (réinit possible) — norme de sécurité.
- **⚠️ Piège trouvé** : Kouider ET Houari ont `role='admin'` (pas 'kouider'/'houari') → `is_super` mis via `update profiles set is_super=true where name='Kouider'`.

### 1.11 Repositionnement accueil « conciergerie complète »
- **Quoi** : hero + tags élargis (voiture/immo/import/séjour), section « Nos services » passée de **3 à 6** (location, vente, import, immo, packs, conciergerie sur-mesure), CTA final « Une demande ? On s'occupe de tout ». Cartes voiture traduites (carburant/boîte/catégorie/bouton via `localizeValue`).
- **Pourquoi** : l'accueil donnait l'impression d'une simple location ; Kouider veut qu'on comprenne que c'est une conciergerie qui fait TOUT.

- **Tests réels effectués** (clés Groq+Gemini fournies, à régénérer) : chat+outils+vraies données (15 voitures), vision (« Fiat 500 grise »), TTS (Gemini), STT (Groq Whisper a retranscrit « Bonjour bienvenue chez Fik Conciergerie »).

## 3. APP DZARYX ↔ SITE (connexion)

- **Insight clé** : app et site partagent la **même base Supabase** → CA, Clients, Agenda lisaient DÉJÀ les réservations du site.
- **Trou comblé** : la page **DEMANDES** lisait le bot WhatsApp désactivé → rebranchée sur **`/api/demandes`** (nouvelle route backend) qui agrège **leads + dossiers + import + résas en attente**. Filtres, relance WhatsApp dans la langue, lien Gérer.
- **Agir depuis l'app** : **`POST /api/demandes/update`** (proxy serveur→serveur vers les APIs du site, pas de CORS) → **accepter/refuser une réservation** + marquer un lead conclu **directement dans l'app** (déclenche email/WhatsApp auto). Boutons dans DemandesScreen.
- **Pourquoi ce choix** : proxy backend plutôt qu'appel direct app→site (CORS) ; les stages riches dossier/import restent gérés sur le site (bouton « Gérer »), seules les actions fréquentes (accepter résa) sont in-app.
